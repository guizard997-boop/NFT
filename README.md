# TON NFT Monitor Bot

Telegram-бот на **aiogram 3** для мониторинга NFT-коллекций в сети TON через
**TonAPI**. Отслеживает покупки, действия на маркетплейсе (листинги, ставки,
изменение цены) и прямые передачи NFT, мгновенно присылая уведомления
подписчикам со ссылкой на Getgems.

## Структура проекта

```
ton-nft-bot/
├── main.py            # точка входа: бот + мониторинг + health-check сервер
├── config.py           # переменные окружения и константы
├── handlers.py        # команды бота (/start, /status, /test, /add, /list)
├── monitor.py          # опрос TonAPI, классификация событий, рассылка
├── storage.py          # хранение подписчиков и состояния в JSON
├── tonapi.py            # обёртка над TonAPI
├── requirements.txt
├── .env.example
└── data/
    ├── subscribers.json   # база подписчиков (создаётся автоматически)
    └── state.json          # прогресс мониторинга (создаётся автоматически)
```

## Команды бота

| Команда         | Доступ   | Описание                                                        |
|-----------------|----------|------------------------------------------------------------------|
| `/start`        | все      | Регистрирует пользователя и показывает его Telegram ID           |
| `/status`       | все      | ID, статус админа, кол-во подписчиков, всего обработано событий   |
| `/test`         | админ    | Рассылает тестовое уведомление о сделке всем подписчикам          |
| `/add <ID>`     | админ    | Добавляет Telegram ID вручную                                     |
| `/list`         | админ    | Показывает список всех подписчиков                                 |

## Установка и запуск локально

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
   - `ADMIN_ID` — ваш Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot))
   - `TONAPI_KEY` — (не обязателен) ключ с [tonconsole.com](https://tonconsole.com), повышает лимиты запросов
   - `NFT_COLLECTIONS` — адреса коллекций через запятую
3. Запустите:
   ```bash
   python main.py
   ```

## Деплой на Railway

Весь конфиг бот берёт **только из переменных окружения** — файл `.env`
нужен исключительно для локального запуска и в Railway не участвует.
Railway сам слушает HTTP-порт из переменной `PORT`, и бот уже это
поддерживает через встроенный aiohttp health-check сервер (`GET /` и
`GET /health` → `200 OK`), чтобы Railway не перезапускал контейнер.

1. Загрузите проект в Git-репозиторий и подключите его к Railway (New Project → Deploy from GitHub repo).
2. Откройте сервис → **Variables** и добавьте:
   | Переменная        | Обязательна | Описание                                              |
   |-------------------|:-----------:|--------------------------------------------------------|
   | `BOT_TOKEN`       | да          | Токен от [@BotFather](https://t.me/BotFather)           |
   | `ADMIN_ID`        | да          | Ваш Telegram ID ([@userinfobot](https://t.me/userinfobot)) |
   | `NFT_COLLECTIONS` | да          | Адреса коллекций через запятую                          |
   | `TONAPI_KEY`      | нет         | Ключ с [tonconsole.com](https://tonconsole.com), снимает лимиты |
   | `POLL_INTERVAL`   | нет         | Интервал опроса TonAPI в секундах (по умолчанию 20)     |
   | `EVENTS_LIMIT`    | нет         | Сколько событий запрашивать за опрос (по умолчанию 20)  |
   | `PORT`            | нет         | Railway подставляет сам, задавать вручную не нужно      |
3. Команда запуска (Start Command): `python main.py`.
4. Если забудете обязательную переменную — бот не запустится и сразу
   напишет в логах Railway, какой именно переменной не хватает
   (`config.validate_config()`), вместо тихого падения.

⚠️ Файлы `data/subscribers.json` и `data/state.json` хранятся на локальном
диске контейнера. На некоторых хостингах (например, Render с эфемерной
файловой системой на бесплатном плане) они могут сбрасываться при
пересборке/рестарте — для постоянного хранения в проде лучше подключить
внешнее хранилище (Redis, Postgres, вольюм с постоянным диском и т.п.).

## Важное замечание про TonAPI

Бот использует публичный эндпоинт TonAPI v2 `GET /v2/accounts/{address}/events`
и классифицирует события по полю `action.type` (`NftPurchase`,
`NftItemTransfer`, а также любые типы, похожие на активность аукциона/продажи
— `Auction`, `Sale`, `Listing`, `Bid` и т.п. — см. `monitor.classify_action`).

TonAPI — внешний развивающийся сервис, и точный набор типов действий /
названия полей могут отличаться от указанных здесь либо измениться со
временем. Если после запуска бот не находит ожидаемые события или сумма/адрес
приходят пустыми — откройте актуальную документацию
[tonapi.io/api-v2](https://tonapi.io/api-v2), посмотрите реальный ответ для
вашей коллекции и подстройте функции `classify_action()` и
`extract_details()` в `monitor.py` под фактическую схему ответа.

## Как это работает

1. `monitor.monitor_loop` раз в `POLL_INTERVAL` секунд опрашивает каждую
   коллекцию из `NFT_COLLECTIONS` через TonAPI.
2. Новые (ещё не виденные) события классифицируются на покупку /
   маркетплейс / передачу.
3. Для каждого релевантного события формируется сообщение с типом события,
   суммой в TON, сокращённым адресом NFT и кнопкой-ссылкой на Getgems, после
   чего оно рассылается всем адресам из `data/subscribers.json`.
4. Счётчик обработанных событий и последние ID событий каждой коллекции
   сохраняются в `data/state.json`, чтобы не дублировать уведомления и не
   слать историю заново после перезапуска.
